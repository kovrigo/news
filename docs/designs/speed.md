# Speed

Замер 1 октября 2026 года, локальное демо на встроенных придуманных сюжетах.

## Итог

Медиана каждого шага редактора не больше 0,52 секунды, даже при процессоре, замедленном в 4 раза. Исключение одно: после правки надпись «Сохранено» появляется через 1,6–2 секунды. Из них 1,5 секунды — намеренная пауза: правка уходит, когда человек перестал печатать.

Найдено узкое место: страница отдавалась в режиме разработки. Код был несжатым, React работал в медленной отладочной сборке. Теперь демо отдаёт сжатую рабочую сборку. Код страницы уменьшился с 1327 до 271 КБ. Журнал на 500 строк при замедленном процессоре теперь показывается за 0,43 секунды вместо 0,95.

## Условия замера

- Сервер и браузер на одной машине: AMD Ryzen 9 7950X3D, 4 ядра для этой машины, Bun 1.4.2.
- Сервер запущен через paneweb, адрес только на этой машине.
- Браузер: Chromium 151.0.7922.34 без окна, окно 1280×800.
- Каждый прогон начинается со сброса демо и с пустого кеша браузера.
- По 5 прогонов на каждый набор условий. Ниже медиана, в скобках самое быстрое и самое медленное значение.
- Два состояния демо:
  - обычное: встроенные сюжеты, файл состояния 49 КБ;
  - большая история: к журналу добавлено 7000 строк, файл 1,8 МБ при пределе 2 МБ.
- Две скорости процессора: обычная и замедленная в 4 раза. Замедление приближает слабый офисный ноутбук.
- Время шага: от нажатия до появления результата на экране, проверка на каждом кадре.
- Утверждают и выгружают под Павлом Тестовым, правит Ольга Демина.

## Что изменено

- Демо отдаёт страницу в рабочей сборке, а не в режиме разработки.
- Последствие для разработчиков: правка кода страницы видна только после перезапуска сервера.
- Добавлен скрипт замера. Он сам сбрасывает демо до и после замера.

## Сервер

Каждый запрос читает и записывает весь файл состояния. Поэтому ответ сервера растёт с историей. Значения после исправления, обычный процессор:

- обычное демо: 3–6 мс на любой запрос;
- большая история: чтение 10–12 мс, изменение 22–26 мс: правка, утверждение, выгрузка.

Экран сюжета спрашивает сервер каждые 2 секунды. При большой истории это около 10 мс работы сервера на каждый открытый сюжет. Для одного-двух человек это незаметно.

## Видимые задержки

- «Сохранено» появляется через 1,6 секунды после последней буквы, на медленном процессоре через 2 секунды. Так задумано: правка уходит одним запросом после паузы в печати.
- Журнал с большой историей на медленном процессоре показывается за 0,4–0,5 секунды. На обычном процессоре за 0,14 секунды.
- Первый экран на медленном процессоре около 0,45 секунды.
- Остальные шаги не дольше трети секунды даже на медленном процессоре.

## Ограничения

- Это локальное демо. Сервер и браузер на одной машине, сети редакции нет. Задержка сети к каждому шагу не добавлена.
- Настоящих моделей нет. Обработка идёт через заглушки. Время обработки нового сюжета настоящими моделями не измерено и здесь не оценивается.
- Большая история составлена из копий строк встроенного журнала. Размер настоящий, содержание повторяется.
- Замедленный процессор — эмуляция в браузере, не настоящий ноутбук. Серверная часть при этом не замедлялась.
- Измерен один человек за раз. Одновременную работу нескольких человек не измеряли. Сервер обрабатывает запросы по одному.
- Только Chromium без окна, только ширина 1280. Телефон не измеряли.
- Файл состояния ограничен 2 МБ. Дальше демо не растёт, и замер дальше этого предела не нужен.
